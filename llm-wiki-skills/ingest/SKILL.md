# ingest — 编译期调度

把一个原始文件变成 `wiki/` 里的页面。**只写库，不读库回答问题**（那是 `wiki-query` 的事）。

## 开工前必读

1. `D:\workspace\ai_kb_base\second-brain\agent.md` —— 规则全在这儿，本 skill 只讲调度顺序，不重复规则
2. `D:\workspace\ai_kb_base\second-brain\wiki\_templates\` —— 七个模板（concept / entity / method / metric + doc / digest / topic），按 type 选对应那个，四类节点模板段名统一为七段

**没读这两样就动手，产出一定不合规。**

## 九步

| 步 | 动作 | 产出 | 卡在哪 |
|---|---|---|---|
| 1 | **落地** 原文写入 `raw/<来源>/<标题>.md` | 源文件 + frontmatter | 文件名**不带日期** |
| 2 | **判重** 走 agent.md 判定点 A | 一句话判定 | 同源重复就**提前结束** |
| 3 | **抽取** 按第八节契约出 JSON | 结构化中间态 | 先 JSON 再写 MD，不许直接手写 md；**先判原文有无章节结构**，有章节走全面覆盖（见下） |
| 4 | **校验** `high` 断言逐字回原文比对 | 通过/不通过 | 不通过就回第 3 步重抽 |
| 5 | **写文档页** 套 `doc-template.md` | `wiki/summaries/<日期>-<标题>.md` | 日期前缀不可省；frontmatter 必须含 `raw_hash`（`python _tools/recompile.py --init` 生成） |
| 6 | **处理概念** 走判定点 B | 新建或追加概念页 | **默认追加，不是新建** |
| 7 | **补全索引与topic-map** | `index.md` **重建**（含文档页、概念页、沉淀页全部条目）；`topic-map.md` 对应分组补齐 | 不许只加一条就完事；用 `rebuild_index_full.py` 从头生成 |
| 8 | **体检** | 断链数 / 孤岛数 / **实质保留率** / **本体 12 约束** | 断链不为 0、保留率 <99%、或本体 error 不为 0 就回第 3 步 |
| 9 | **写处理日志** | `logs/<日期>-<标题>.md` | 用 `_tools/gen_ingest_log.py` 生成，见下节 |

## 三个必须停下来的地方

**① 判定点 A 说「同源重复」** —— 别往下走。同一篇编两遍，库里会有两个文档页抢同一个概念。

**② 概念页已存在** —— 判断依据只有一句：**这一页里是否会新增一段此前没有的内容？**

- 会 → 追加到对应小节
- 不会，只是换个说法 → **只在「出处」加一行**，正文不动
- 说法**相矛盾** → 在「常见误区」记下分歧，**两条都留，绝不覆盖**

**③ 体检断链不为 0** —— 别手工补链接。断链说明规则有问题（命名错了、或给未建页加了双括号），改 `agent.md` 再重跑。手补会被下次重跑覆盖。

## 三条禁令

| 禁止 | 原因 |
|---|---|
| 为读不出内容的 source 生成空壳页 | 会把 `wiki/` 淹成一片空页，真内容反被埋掉 |
| 读不出的内容靠猜补上 | ASR 听错、OCR 认错的词会被当知识永久记住 |
| 一次批量编几十篇 | 单篇没调准就批量，出来是几十份同样的错误 |

## 技术坑（都会静默失败，不报错）

| 坑 | 现象 | 正确做法 |
|---|---|---|
| 证据跨 markdown 标记 | 原文 `**import**java.sql.DriverManager;`，剥空白后仍含 `**`，逐字比对必失败 | 证据从标记之后开始引，只取 `java.sql.DriverManager;` |
| 表格只引半段 | `\| json.dumps \| 将 Python 对象编码成 JSON 字符串 \|` 是连续行 | 整行引；绕不开就降 `medium` 并说明「结构化内容，非原文明说」 |
| heredoc / `python -c` 里写正则 | `re.search(r"...\s*(.+)")` 静默返回 `None`，制造「全库无此字段」的假警报 | 验证类脚本一律 Write 成 `.py` 再跑，不用 heredoc |
| 用正则替换列表重建 index | 列表里的空行会打断 `(?:- .*\\n)+`，每次只替换前半段，跑几次累积成多份重复 | 用 `rebuild_index_full.py` 从头生成，不基于旧文件 |
| 直接改 `raw/` 正文 | `raw/` 是导出快照，用户在有道云改字不会同步过来 | 改本地时在 front-matter 加 `amended: <日期> <改了什么> <依据>`，保住溯源 |

另外两条口径：

- **凭据类**（密码/私钥/Token）做屏蔽页，不进索引、不进概念网络，**保持孤岛是对的**，别为消掉孤岛计数给它加链接
- **原文笔误**（「请求中/请求时」「ViewResoler」「不选着」）证据照抄，另加注说明，不要顺手改原文

再补三条（2026-11-07 踩过）：

| 坑 | 现象 | 正确做法 |
|---|---|---|
| 表格/列表行之间插空行 | 生成的页面里 markdown 表格被拆成一行一行，Obsidian 不渲染成表 | 渲染时 `-`、`|` 开头的行紧凑排列，只在普通段落之间加空行 |
| 名称+标签按末尾字数截断 | 「两个重要极限公式源头」被切成「两个重要」+「极限公式源头」 | 建标签词表做**最长匹配**，不要按字数或正则 `(.+?)([一-龥]{2,6})$` 硬切 |
| 报数字不核对单位 | 说「43 个知识点未建页」，实际是 `57 条目 − 14 概念页` 的错算 | 概念页数 ≠ 知识点数，一个概念页可装多个条目；报数前先跑归属核对 |

再加一条硬规矩（2026-11-06 踩过）：

- **外部文件必须直接落 `raw/`，不许在工作区根自建中转目录**。下载 HTML / PDF / 图片时，目标路径直接写 `raw/<文档|网页|视频|其他>/<标题>.扩展名`；不许先扔进自建的 `_inbox`、`tmp`、`download` 之类目录再搬。真要中转，用系统临时目录。
- **原件与转换后的 md 同目录并列**：`xxx.html` + `xxx.md` 放一起，md 的 frontmatter 加 `original: xxx.html（同目录，大小，形态）` 指向原件。原件是重转的唯一依据，不能丢在库外。

## 索引与topic-map必须补全（第 7 步）

入库不是只写页面就算完。每次必须同时更新两处导航：

| 文件 | 要求 |
|---|---|
| `index.md` | **从头重建**（`_tools/rebuild_index_full.py`），含全部文档页、概念页、沉淀页清单。不要用正则局部替换——空行会打断匹配，旧内容会残留累积 |
| `wiki/topic-map.md` | 新建的概念页必须进对应分组；分组不存在就新建。topic-map是「找方向」的入口，缺了它新概念页等于隐身 |

判断标准：**新概念页在topic-map里能搜到名字**，文档页在 index 里能搜到条目。

> 两条边界：
> 1. **不要自创新文件或新目录**——索引就是 `index.md`，主题导航就是 `topic-map.md`，不另建"入口页""今日更新"之类。规则没定义的位置一律不加。
> 2. index 生成文档页摘要时按 90 字截断，摘要里的 `[[长文件名]]` 会被切成半截，制造假断链。摘要要么写短，要么别把长链接放进去。

## 每次入库都要写处理日志（第 9 步）

日志写到 `D:/workspace/ai_kb_base/logs/<日期>-<标题>.md`，用脚本生成：

```bash
python _tools/gen_ingest_log.py --title "<标题>" \
    --src "<原文相对 second-brain 的路径>" \
    --docs "<文档页文件名，逗号分隔>" \
    --new-concepts "<新建概念页名，逗号分隔>" \
    --append-concepts "<追加概念页名，逗号分隔>" \
    --digests "<沉淀页，无则留空>" \
    --form "有章节 / 无章节"
```

日志固定四段：**原始是什么**（路径、规模、形态、原件）→ **生成了什么**（文档页、概念页、沉淀页各自清单与规模）→ **索引与topic-map** → **校验结果**（断言、保留率）。

脚本会自动跑 `check_claims.py --all` 与 `check_coverage.py`，把校验读数写进日志。

## 按原文形态分流（2026-11-07 用户规则）

| 原文形态 | 抽取策略 |
|---|---|
| **有章节**（教材、教程、带章/节的长文） | 按 **章 → 节 → 知识点** 逐层整理，每个大类、小类的核心知识点**全面覆盖**；章级与节级主题都可建页，不再用「≥2 篇或前置」卡掉 |
| **无章节**（单篇笔记、随笔、问答） | 只提取核心知识点，按 `agent.md` 第五节三条门槛决定建页 |

有章节时还要保留**章级导览内容**：各章导读、全书主线、学习路线。它们不是知识点，但决定知识的位置关系，丢了会让章节之间散架。

单一技术步骤（洛必达、三角代换、待定系数法）不单独建页，归入所属章/节页的应用节，**但其原文内容必须完整保留**。

## 教材型原文：两层结构 + 保留率验收

教科书、系统教程、章级长文**不能只写提炼**。规则见 `agent.md` 第五·五节，调度上这么做：

**① 先把原文结构化，不要凭记忆摘句**

用脚本把原文按条目切开（定义/为什么/性质/用处等自然段），存成 JSON 中间态。同济版高数的做法：`_tools/parse_gaoshu.py` → `gaoshu_items.json`（57 条目、732 行正文，无空条目）。

**② 页面写两层**

- 知识本体（定义、公式、定理、题型）→ 由脚本从 JSON 自动渲染进页面，**原文 100% 保留**
- 结构化提炼（归类、类比、边界、关系）→ 手写，放在原文节之外

**③ 用保留率验收，不用感觉**

```bash
python _tools/check_coverage.py <原文.md> <概念页1.md> <概念页2.md> ... <文档页.md>
```

输出实质保留率与缺失样例。**≥99% 才算完**，缺失样例逐条补或写明理由。

**③·五 颗粒度要下探到知识点，并逐条编号**

只做章级、节级不算全面。原文每节内部的**每条性质、每条用法**都是独立知识点，必须：

1. 编号：`节号-D`（定义）、`节号-P<n>`（性质）、`节号-U<n>`（用处）
2. 概念页的「定理与运算律」「题型与场景」两节用同套编号
3. 另建 **`wiki/summaries/<日期>-<标题>知识点总索引.md`**（脚本 `build_kp_index.py`），按章列出全部知识点，每条带编号与归属概念页

**验收四项必须对上**：应有编号数 = 实际出现数 = 无缺失 = 无多余。同济版高数：57 定义 + 203 性质 + 222 用处 = **482 条，缺 0、多 0**。

> 编号是元数据，`check_coverage.py` 比对时会自动剥离 `` `3.2-P1` `` 这类标记，不影响保留率判定。

**④ 手工补丁必须写回生成器**

手改产物文件后，重跑生成器会冲掉。本轮的解法：补充节写进 JSON 的 `extra` 字段，由生成器统一渲染。

**本次可复用的脚本**（都在 `_tools/`）：

| 脚本 | 用途 |
|---|---|
| `parse_gaoshu.py` | 按条目切四段，输出结构化 JSON |
| `extract_preamble.py` | 提取各章前言与整章（主线、学习路线） |
| `build_gaoshu_full.py` | 文档页生成（知识地图 + 分组断言 + 章前言） |
| `build_concepts.py` | 概念页生成（七段模板 + 四段原文 + extra 补充节） |
| `check_coverage.py` | **逐行保留率验收**（通用，任何原文可用） |
| `verify_ev.py` / `verify_ev2.py` | 批量预验证据是否逐字存在于原文 |
| `list_clean.py` | 列出条目中不含 `*` 的句子，供挑证据 |

## 批量前先做金标准

挑 1 篇最有代表性的跑完整九步，**逐条人工核对**，发现的问题写回 `agent.md`，重跑，直到不再改任何规则。

再开始批量。

## 交付时说什么

不要只说「完成了」。要说：

- 新建了哪几个文件（给路径）
- 概念页是**新建**还是**追加**，追加到哪一段
- 有没有判定为冲突的断言（有就列出来）
- 体检结果：断链 X%、孤岛 X%
- **本体校验**：`check_ontology.py` 的 error / warn 读数；新建知识节点时报它的 `type` 判定依据（四类之一），实体页另报 `entity_type` 子类
- **实质保留率**（教材型原文必报）：`check_coverage.py` 的读数 + 缺失样例怎么处理了
- **处理日志路径**：`logs/<日期>-<标题>.md`（由第 9 步生成）
